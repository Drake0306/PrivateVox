# PrivateVox 0.4.0 alpha 1

Third alpha. Two big additions since 0.3.0: a PrivateVox on one machine can do the work for another on the same network (use the PC's GPU from the Mac), and the dictation itself got smarter: a personal dictionary, spoken languages, kept audio with replay and re-run, and a long-form document view. On macOS the clipboard restore is now driven by the app actually reading the paste, and the pill warns when a password field has secure input on.

**macOS on Apple Silicon** is the platform this was built and tested on. **Windows** and **Linux** builds come from the automated build and have not been run by a person yet; please report what happens.

## What is new

- **Host mode** (Settings → Network). Switch on "Act as host for other machines" on the PC; on the Mac switch on "Use a host on this network" and enter the PC's `ip:port`, or press "Find hosts on this network" and Add the one it finds. While the host answers, what you dictate on the Mac is transcribed and polished on the PC and nothing is loaded on the Mac; the memory strip shows the PC's figures. When the host is not reachable the Mac does the work itself and says so. Both machines keep a history (rows marked "host" and "via PC"); a toggle in the History header shows the PC's list from the Mac.
- **Personal dictionary** (Settings → Dictation): names and jargon, one per line. Whisper is told to expect them and a fuzzy pass fixes near-misses afterwards.
- **Spoken languages**: one means a fixed decode; several means Whisper picks per clip from your list.
- **Keep audio clips** (off by default): Play and Re-run with another model from history.
- **Open as document** on long dictations: paragraphs, Copy all, Markdown export.
- **macOS paste**: the old clipboard comes back only after the app has read the paste. Secure-input warning in the pill.

## Install

### macOS (Apple Silicon, macOS 12 or newer)
1. Download `PrivateVox_0.4.0_aarch64.dmg`, open it, drag PrivateVox to Applications (replace the old one). Settings and history are kept.
2. Unsigned build: on first launch right-click the app → Open → Open, or run once in Terminal: `xattr -d com.apple.quarantine /Applications/PrivateVox.app`
3. Permissions from the panel's **Setup** tab: Microphone, Accessibility (to paste), Input Monitoring (for the hold key). Quit and start again after granting Accessibility or Input Monitoring.
4. For polish on this Mac: install [Ollama](https://ollama.com) and run `ollama pull qwen2.5:3b`.

### Windows (x64, Windows 10/11, a Vulkan-capable GPU)
1. Download `PrivateVox_0.4.0_x64-setup.exe` (per-user installer) or `PrivateVox_0.4.0_x64_en-US.msi`. SmartScreen will warn because the build is unsigned: "More info" → "Run anyway".
2. Hold **Right Alt** to talk, or tap **Ctrl+Shift+Space**.
3. To serve a Mac: Settings → Network → "Act as host for other machines"; allow PrivateVox through the Windows firewall when asked. LM Studio or Ollama on the PC are found automatically for polish.

### Linux (x64, X11)
`PrivateVox_0.4.0_amd64.AppImage` (make it executable), the `.deb` or the `.rpm`. Vulkan-capable GPU, PulseAudio or PipeWire, X11 for the hold key.

## Known limitations
- Builds are not code-signed. Windows and Linux are untested by a person; the Mac-to-PC path has been tested with one Mac playing both roles, not yet with a real second machine.
- Long dictations with several spoken languages decode every chunk with the first language.
- Only manual `ip:port` and mDNS on the same subnet; no internet access, by design.
