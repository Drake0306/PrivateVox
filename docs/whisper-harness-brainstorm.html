Whisper Harness

A hold-a-key, talk, release, and the text lands where your cursor is dictation tool. Runs fully local on an AMD Windows box or an M1 Mac, keeps Whisper warm in GPU memory, and remembers everything you dictated.

The moment it exists for

You are in Slack, VS Code, a browser form, anywhere. You hold the hotkey, say two sentences, let go. About two seconds later clean punctuated text appears at the cursor, as if you had typed it. No window switching, no upload, no account. If you got it wrong you open the little history panel, fix the line, and copy it again.

That is the whole v1. Everything else on this page is either in service of that moment or parked in the idea bank at the bottom.

The pipeline yours

1Hotkey downGlobal listener, works in any app. Pill pops to "Listening".~0 ms
2CaptureMic at 16 kHz mono straight into a buffer. Nothing hits disk by default.while held
3Hotkey upTrim leading/trailing silence with a voice-activity detector.~20 ms
4WhisperModel already resident on the GPU. Returns raw transcript.0.5–1.5 s
5LLM polishOptional. Punctuation, filler removal, a "mode" prompt (email, bullets, code).1–2 s
6PasteWrite clipboard, send ⌘V / Ctrl+V to the front app, restore old clipboard.~50 ms
7RememberRaw + polished text, app name, duration, mode saved to local history.async

Timings are rough targets for a 10-second utterance on an M1 or an RX 6600-class card. We benchmark in the first week and tune from there. "LLM polish" can be switched off for a sub-second path.

The floating pill yours

Frameless, transparent, always on top, draggable anywhere on the screen and it remembers where you left it. It is tiny at rest and only grows while it has something to say. Click the states below to see each one. Drag the pill itself to feel the idea.

Hold ⌥ to talk

Idle shows the current hotkey so you never forget it. Listening shows a live level meter and a timer. Pasted shows the first words for two seconds and then shrinks back. Right-click or click the pill opens the history panel below it.

The link you sent is openai/whisper-large, the original 2022 "large" (v1). It still works, but two newer checkpoints from the same family are strictly better for this job.

yours All three highlighted rows (large-v3, large-v3-turbo, distil-large-v3) ship together and you switch between them from the history panel. Turbo is what loads at first launch. Switching unloads the current model and loads the new one, roughly one second on an M1 or a mid-range AMD card, and your choice is remembered across restarts. Only one is resident at a time so the VRAM budget below stays the same whichever you pick.

The app ships with a model manager that downloads the three from Hugging Face with a progress bar, picks the quantization that fits the GPU it detects, and has a "benchmark this model" button so you can see words-per-second on your own hardware.

What fits in 8 GB of VRAM

Your Windows card is an RX 9070 with 16 GB, so this table is the worst case rather than your case: an 8 GB card or an 8 GB M1. Whisper is the cheap part. The LLM polish stage is what eats memory, so it is sized to leave headroom for whatever game or browser is also running.

Tauri means the UI is plain HTML/CSS/JS (or any framework you like) and the Rust side is a few hundred lines: audio capture with cpal, Whisper via whisper-rs, SQLite via the Tauri SQL plugin. The engine sits behind one trait so a sidecar (mlx-whisper on Mac, a remote GPU box) can slot in later without touching the UI.

One practical wrinkle: Tauri's global-shortcut plugin needs a real key combination like Ctrl+Space. If you want "hold a single modifier" like Right ⌥ the way Wispr Flow and superwhisper do, we add a low-level key listener (rdev) for that one job. Both are doable; I plan for both from day one.

Exit and crash paths yours

However the app stops, the GPU and RAM it held must come back. There are four ways it can stop, and each gets its own handling.

How it stopsWhat happensWho frees the memory
Normal exit (tray Quit, ⌘+Q, window close)Finish or cancel any in-flight dictation, flush history to SQLite, drop the Whisper context (frees the GPU buffers), stop the audio stream, release the hotkey hook, remove the lock file, then exit.The app, in order, in under a second.
Asked to stop by the OS (SIGTERM / SIGINT on Mac, WM_CLOSE or console Ctrl event on Windows, logout, shutdown)Same path as normal exit, triggered from a signal handler with a two-second deadline. If the deadline passes, exit anyway.The app, falling back to the OS.
Force closed (Task Manager End task, Activity Monitor Force Quit, kill -9)No app code runs. The engine worker sees its pipe to the app close and exits at once; the OS reclaims both processes' RAM and the Metal or Vulkan driver reclaims the GPU allocations as the handles close. No orphan is left holding VRAM.The worker's pipe watch, then the OS and GPU driver.
Crash (panic, driver fault, out of memory)A crash handler writes a short report and exits. Memory is reclaimed as in force close. On the next launch the stale lock file tells the app it died uncleanly, so it opens with a "last session ended unexpectedly" line and offers to send the report nowhere, just show it.The OS and GPU driver; the app only reports.

Rules that make this safe my call

  • Engine in a child worker, never a detached helper. Revised after reading Handy's source: the native engine runs in a worker process the app spawns and talks to over pipes. The worker exits the instant the parent's pipe closes, so a force-closed app strands no VRAM, and a driver crash or hang in the worker is recovered by respawning it instead of taking the app down. What stays forbidden is a detached server nobody owns.
  • One owner for the model. A single engine object owns the Whisper context. Loading, swapping between the three models and unloading all go through it, so there is exactly one place that frees GPU memory and it is also the one called on exit.
  • History writes are atomic. SQLite in write-ahead mode, each dictation committed as one transaction. A crash mid-write loses at most that one entry and never corrupts the file.
  • Lock file as a heartbeat. Written on start, removed on clean exit. Its presence at launch means the last run died, and it also stops two copies running at once.
  • Explicit Pause and timed unload. Tray menu "Pause and unload" drops the model from the GPU without quitting, for when you want the memory back for a game. The automatic version is the idle timer: you set the number of minutes in Settings (1 to 240, or Never, default 10) and can change it whenever you like. yours Both go through the same single unload path as exit.
  • Clipboard restore survives a crash. The old clipboard is saved to disk before paste, so an interrupted paste never leaves your clipboard holding the transcript.
The one case no app can fix on its own is a GPU driver hang, where the driver itself stops responding. That is rare on current Metal and Vulkan drivers, and the OS resets the device. The watchdog is a 30-second timeout on any single Whisper call: if it fires, the app drops the context, reloads the model, and tells you in the pill.

Hotkey and paste mechanics yours

Two ways to trigger

  • Push-to-talk. Hold the key, speak, release. Natural for short utterances, impossible to forget it is on.
  • Toggle. Tap to start, tap to stop. Better for long dictation when holding a key gets tiring.

Both exist, each bindable to its own key. A third binding, "dictate to clipboard only, don't paste", covers the case where the front app is something you do not want text shoved into. my call

How the paste actually happens

  1. Save whatever is on the clipboard.
  2. Put the transcript on the clipboard and send ⌘+V or Ctrl+V to the frontmost app.
  3. After a short delay, restore the old clipboard contents.
  4. Fallback for apps that block paste (some terminals, remote desktops): type the text keystroke by keystroke.

The LLM polish stage open

Whisper gives you decent punctuation but it keeps every "um", repeats your false starts, and has no idea you are writing an email. A small LLM pass fixes that in a second. It also unlocks "modes", which is where this becomes more than dictation.

ModeWhat the prompt asks forWhen
RawNo LLM. Whisper output as is.Speed, or when you trust yourself.
CleanRemove fillers and false starts, fix punctuation, keep your words. Default.Chat, notes.
EmailClean plus paragraphs, greeting and sign-off left as spoken.Mail clients.
BulletsTurn a rambling list into tidy bullet points.Docs, tickets.
CodeSpoken identifiers become snake_case or camelCase, "open paren" becomes (.Editors, terminals.
TranslateWhisper's built-in translate-to-English, no LLM needed.Speaking another language.
AskTreat the speech as a question, paste the answer instead.Quick lookups without leaving the app.

yours Local first, LAN second. The polish LLM runs on the same machine when it can. A second machine on the same Wi-Fi or LAN, reached by IP and port, can be added as another endpoint, and once added it is used automatically whenever it is reachable and dropped automatically when it is not. That is what "seamless" means here: add it once, never think about it again. The connector speaks the OpenAI-compatible chat API, which LM Studio, Ollama and llama.cpp all serve, so a LAN box needs nothing more than one of those running with "serve on network" on.

With the RX 9070's 16 GB on the Windows side, an 8B polish model (Qwen 2.5 7B class) is the comfortable default there, and that PC becomes the natural LAN endpoint for the Mac. LM Studio and llama.cpp run on it through Vulkan today; ROCm support for RDNA 4 is recent, so the spike benchmarks both and we ship the faster stable one.

Things it should not become

  • A meeting recorder. System-audio capture, speaker labels and summaries are a different product with different privacy stakes.
  • A cloud service. Local by default, always. Cloud LLM is an opt-in with a visible indicator on the pill.
  • A note-taking app. History is a scratch log you copy out of, not a place to organize your life.
  • Slow to start. If pressing the hotkey ever waits for a model to load, the tool has failed. Warm model is non-negotiable.

Proposed v1 and build order my call

  1. Engine spike (throwaway). whisper.cpp with large-v3-turbo on both machines. Measure load time and seconds-of-audio-per-second with Metal and with Vulkan. This decides everything else, so it goes first.
  2. Tauri shell. Transparent draggable pill, tray icon, settings window, SQLite history, and the exit path (signal handlers, lock file, model unload) built in from the start rather than added later.
  3. Hotkey → capture → Whisper → paste with the Raw and Clean modes. This is the first usable build.
  4. History panel. List, search, edit, copy, delete, re-paste, export.
  5. Model manager and first-run setup (permissions walkthrough, mic test, model download).
  6. Polish modes and dictionary. Email, Bullets, Code; LLM endpoint setting; personal dictionary; undo last paste; configurable idle unload.
  7. Packaging. Signed .dmg for Mac, installer for Windows with the Vulkan build.

After that, in the order I would take your remaining picks: language pinning and keep-audio (small), long-form notes (toggle mode plus a document view), live preview (needs streaming Whisper and a VRAM check), then the engine work: MLX on Mac and the remote engine, both of which slot behind the engine trait from step 2.

Two ways forward open

A. Own codebase, borrow from Handy. Build to this design and lift proven MIT pieces with attribution where they save weeks: paste reliability, overlay positioning, Vulkan build config, download with mirror fallback. Clean architecture, a project that is yours to open source under its own name. Slower to the first working build.
A. Keep Handy open in a second window as the reference implementation whenever a platform quirk bites.
B. Fork Handy, rebrand, add the missing features. Working dictation on day one. You inherit a React UI and someone else's structure, track or diverge from upstream, and the open-source story becomes "a Handy fork with X". Handy's licence requires a new name and icon either way.
