Harness vs Handy

What Handy has today, and what the Whisper Harness is going to do. Where the Harness does the same thing it is because Handy's way is right, and in fourteen places it is Handy's way we are taking.

What each one does

Handy today

  • Press a shortcut, speak, release; text is pasted into the front app.
  • Whisper Turbo and Large-v3, plus Parakeet, Moonshine, Canary and custom GGML models, through its own ggml library transcribe.cpp.
  • Metal on Apple Silicon, Vulkan on Windows and Linux, CPU fallback with runtime variant selection.
  • Engine in a child worker process with crash and hang recovery.
  • Long recordings decoded in chunks while you speak; live text for streaming models.
  • History with audio replay, favourite, delete, retry; retention and limit settings.
  • LLM post-processing with OpenAI, Anthropic, Groq, OpenRouter, Ollama and custom endpoints; multiple prompts.
  • Custom words, filler removal, translate, language detection, idle unload presets, tray, CLI and Raycast control.
  • MIT code, ~35k stars, active releases. Name and logo are not open.

Harness, as designed

  • Same core loop, same engine architecture, same decode and paste techniques where Handy's are best.
  • Three Whisper tiers switchable from the history panel: large-v3-turbo, large-v3, distil-large-v3. One resident at a time.
  • A GPU memory strip: total, used by others, cost of the selected model and LLM, Recommended and Best-that-fits, projected usage before loading, per-model benchmark.
  • Local first, LAN second: ordered LLM endpoints with health checks, automatic failover and fail-back, discovery later, and sharing the Whisper engine so the Mac can use the PC's RX 9070.
  • History as a workbench: edit in place, re-polish with another mode, paste again, search, export.
  • Undo last paste. Draggable pill with states. LLM warm-up fired on hotkey down. Idle unload in any number of minutes.
  • Written exit and crash contract on top of the worker-process design: lock-file crash detection, disk-backed clipboard backup, one unload path.
  • Mac first, then Windows on the RX 9070. Personal use first, then open source under its own name.

Why the adopted pieces make transcription faster

Handy sets no special Whisper decode parameters. Its run options carry only the task, the language and the custom vocabulary. The speed is in the pipeline around the model, and that is what transfers:

  • Work happens before the key comes up. Chunks decode while you are still talking; the mic stream is already open; the language is already known; the GPU was prepared at launch.
  • Whisper sees only speech. Pre-roll and hangover keep word edges, true silence is dropped, sub-second clips are padded, and empty input never reaches the model.
  • Output is cleaned without a round trip. Stutters, fillers and vocabulary misses are fixed by rules in microseconds; the LLM gets a shorter prompt or is skipped entirely in Raw mode.
  • Nothing waits on a dead engine. A hung or crashed worker is replaced in the background; the pill reports it and the next hotkey press works.
Our own tuning to measure in the spike, not from Handy: greedy decoding against beam size 5 for the fast tier, flash attention on Metal, and a reduced audio context for clips under 10 s. These need direct whisper.cpp access, which is why whisper-rs stays as the second engine.

Direction

Own codebase, built to the design, taking Handy's MIT-licensed techniques with attribution wherever they are the right answer. Handy stays open in a second window as the reference implementation. Forking Handy or contributing upstream remain possible; the GPU-memory logic will be written as a standalone crate so it can be offered to Handy as a pull request either way.
